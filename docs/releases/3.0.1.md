# Godot Agent Loop 3.0.1

Godot Agent Loop `3.0.1` fixes server startup through `npx` and global
installs, and fails fast when the runtime port is already taken.

## Fixed

- The server now starts when launched through a `node_modules/.bin` symlink.
  `npx` and global installs run `build/index.js` that way; the entry check
  compared the unresolved link path against the module path, never matched,
  and the process exited `0` without starting, which MCP clients reported as
  "Connection closed". The check now compares real paths.
- `run_project` checks the selected `GODOT_MCP_RUNTIME_PORT` before spawning
  Godot and watches startup for a bind failure. When another process owns the
  port, it reports an ownership error instead of connecting to that process.

## Changed

- The README documents `GODOT_MCP_RUNTIME_PORT` overrides, validation, and
  multi-instance port rules.
- Direct integration runs and the E2E harness allocate an isolated runtime port
  per run, and the cross-platform E2E smoke now launches the server through a
  symlink.

There are no tool, schema, or runtime protocol changes.

## Validation

`npm run check` (lint, one build, and the retained unit suite) passes, and the
cross-platform E2E smoke passes locally against Godot 4.7.2 on Linux.

## Install

```bash
npx -y @beremaran/godot-agent-loop@3.0.1
```

Users of `3.0.0` should update their pinned agent adapter or MCP command to
`3.0.1`.
